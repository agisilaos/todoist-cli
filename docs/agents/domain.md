# Domain Docs

This repository uses a single domain context.

When exploring or changing domain behavior:

- Read the [domain glossary](../../CONTEXT.md) and use its vocabulary in code, tests,
  issues, and proposals. Note genuine terminology gaps for domain-modeling work.
- Read [architecture decisions](../adr/) relevant to the change. If a proposal
  conflicts with an ADR, identify the decision and explain why it needs reopening.

For implementation boundaries, use the [architecture overview](../ARCHITECTURE.md);
for behavior contracts, use the [documentation index](../README.md).
