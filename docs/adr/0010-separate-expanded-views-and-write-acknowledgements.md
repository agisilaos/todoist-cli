# Separate expanded views and write acknowledgements

Keep ordinary task-resource representations frozen and give expanded parent/children views and accepted-write fallbacks their own output contracts and schemas. Expanding the v2 allowlist or fabricating a task from mutation input would conceal a collection boundary or unavailable resulting state; separate envelopes trade uniform command shapes for explicit completeness and acceptance evidence while preserving valid existing resource results. Expanded views buffer all direct-child pages before output, and optional task-response failure cannot reverse an established mutation acknowledgement.

The selected task output version applies to nested resources, not to the surrounding envelope. Pagination exhaustion does not promise a concurrent snapshot. See [task editing](../task-editing-design.md) and [ADR-0008](0008-preserve-legacy-task-output-with-a-faithful-projection.md).
